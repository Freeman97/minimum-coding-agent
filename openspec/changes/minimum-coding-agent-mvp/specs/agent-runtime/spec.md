# Spec Delta

## Purpose

定义单 Agent 的 ReAct 执行与多轮会话行为，以及供控制台与 headless 共用的统一事件流契约。

## ADDED Requirements

### Requirement: ReAct 循环

系统 SHALL 以"模型决策 -> 工具执行 -> 结果回注"的循环推进任务，直到模型给出最终回答或达到迭代上限；达到上限时 SHALL 结束本次运行并说明原因。

#### Scenario: 模型请求工具

- **WHEN** 模型返回工具调用请求
- **THEN** 系统执行对应工具，并将结果作为工具消息回注给模型继续推理

#### Scenario: 模型给出最终回答

- **WHEN** 模型不再请求工具调用
- **THEN** 本次运行以该回答结束，并发布运行结束事件

#### Scenario: 达到迭代上限

- **WHEN** 工具调用轮次达到配置的最大迭代次数
- **THEN** 系统终止本次运行并报告已达到迭代上限

### Requirement: 系统提示装配

每次运行前系统 SHALL 组装系统提示，包含 Agent 角色、运行环境（工作区、操作系统、日期、模型名）、工具使用策略与已加载的项目自定义指令。

#### Scenario: 包含运行环境

- **WHEN** 一次运行开始
- **THEN** 系统提示包含当前工作区路径与运行环境信息

#### Scenario: 包含项目自定义指令

- **WHEN** 项目自定义指令已加载
- **THEN** 其内容出现在系统提示中；未加载时运行正常且不注入空内容

### Requirement: 多轮会话

系统 SHALL 在同一会话内保留多轮对话历史，使后续用户输入可引用前文；新会话 SHALL 从空历史开始，不同会话之间的消息与状态 SHALL 相互隔离。

#### Scenario: 引用前文

- **WHEN** 用户在同一会话中先后提出相关请求
- **THEN** 第二次请求的推理可引用第一次的对话内容

#### Scenario: 开启新会话

- **WHEN** 用户开启新会话
- **THEN** 会话历史与 TODO 状态清空，之后的运行从空历史开始

#### Scenario: 会话隔离

- **WHEN** 两个会话先后存在
- **THEN** 消息、工具调用记录与 TODO 状态互不串扰

### Requirement: 可组合上下文压缩管线

系统 SHALL 支持按配置组合多种上下文压缩策略；机械压缩（截断工具输出、按完整轮次丢弃早期消息）SHALL 始终作为最后兜底，保证请求不超过配置预算，且压缩后工具调用与其结果消息保持成对。

#### Scenario: 机械兜底满足预算

- **WHEN** 历史超过配置预算且未启用 LLM 摘要
- **THEN** 先截断大体积工具输出，再按完整轮次丢弃最早消息，直到满足预算

#### Scenario: 未超预算不压缩

- **WHEN** 历史未超过配置预算
- **THEN** 原始消息顺序与内容保持不变

#### Scenario: 工具调用配对完整

- **WHEN** 上下文被压缩
- **THEN** 任何工具调用与其结果消息保持成对，消息顺序合法

### Requirement: LLM 摘要压缩与回退

系统 SHALL 支持可配置的 LLM 摘要压缩：当历史达到摘要阈值时，将较早对话轮次总结为摘要消息，保留系统提示与最近若干轮；摘要压缩失败或超时 SHALL 回退到机械压缩。

#### Scenario: 启用 LLM 摘要

- **WHEN** 配置启用 LLM 摘要且历史达到摘要阈值
- **THEN** 较早的对话轮次被总结为摘要消息，系统提示与最近轮次保留

#### Scenario: 摘要失败回退

- **WHEN** LLM 摘要压缩器出错或超时
- **THEN** 跳过该压缩器并继续后续策略，最终由机械兜底满足预算

### Requirement: 统一事件流

系统 SHALL 以统一事件序列对外发布运行过程，至少包含运行开始、文本增量、工具调用开始、工具调用结束、TODO 更新、运行结束与错误；控制台与 headless 均消费同一事件流。

#### Scenario: 工具调用事件

- **WHEN** 一次运行包含工具调用
- **THEN** 事件按发生顺序发布，且工具调用事件包含工具名称、参数摘要与结果摘要

#### Scenario: 运行出错

- **WHEN** 运行过程中发生模型或工具错误
- **THEN** 发布错误事件，并随后发布运行结束事件

#### Scenario: 消费方一致性

- **WHEN** 控制台与 headless 消费同一次运行
- **THEN** 两者观察到相同的事件类型与顺序

### Requirement: 可脚本化测试

运行时 SHALL 支持注入脚本化的模型响应，使 ReAct 循环与事件流可在没有真实模型端点的情况下被确定性测试。

#### Scenario: 脚本化模型驱动循环

- **WHEN** 注入按脚本返回工具调用与最终回答的模型
- **THEN** 循环按脚本完成，并产生预期的事件序列与状态变化

#### Scenario: 离线测试

- **WHEN** 未配置真实模型端点
- **THEN** 默认测试集可离线运行，真实端点相关测试自动跳过
