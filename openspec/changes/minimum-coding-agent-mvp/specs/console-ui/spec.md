# Spec Delta

## Purpose

定义交互式控制台界面的行为：多轮对话展示、流式渲染、工具执行可视化、计划展示与运行控制。

## ADDED Requirements

### Requirement: 控制台布局

系统 SHALL 提供交互式终端界面，包含对话历史区、输入区与状态栏，并在常见终端尺寸下保持可操作。

#### Scenario: 启动界面

- **WHEN** 用户启动交互式控制台
- **THEN** 界面显示对话历史区、输入区与状态栏，状态栏展示当前模型、工作区与运行状态

#### Scenario: 终端尺寸较小

- **WHEN** 终端尺寸缩小到较小窗口
- **THEN** 关键区域仍可操作，界面不崩溃或错位到不可用

### Requirement: 流式对话渲染

界面 SHALL 在模型输出过程中增量渲染文本，并在结束后保留最终消息；多轮消息 SHALL 按时间顺序显示。

#### Scenario: 增量显示

- **WHEN** 模型正在流式输出
- **THEN** 文本随增量事件逐步出现，而不是等待全部完成后一次性显示

#### Scenario: Markdown 渲染

- **WHEN** 模型输出包含 Markdown 格式
- **THEN** 最终消息按 Markdown 渲染，格式异常的内容不会导致界面崩溃

#### Scenario: 自动滚动

- **WHEN** 新消息或增量内容到达
- **THEN** 视图滚动到最新内容，用户仍可向上滚动查看历史

### Requirement: 工具调用可视化

界面 SHALL 为每次工具调用展示工具名称、参数摘要与执行状态，并在结束后展示结果摘要；失败时 SHALL 明确标识错误。

#### Scenario: 工具开始执行

- **WHEN** 工具调用开始
- **THEN** 出现运行中的工具卡片，展示工具名称与参数摘要

#### Scenario: 工具执行成功

- **WHEN** 工具调用成功结束
- **THEN** 卡片更新为成功状态并展示结果摘要

#### Scenario: 工具执行失败

- **WHEN** 工具调用失败
- **THEN** 卡片标识失败状态并展示结构化错误信息

### Requirement: 输入与运行控制

界面 SHALL 支持 Enter 提交输入、Shift+Enter 换行；运行期间 SHALL 显示忙碌状态并允许用户取消本次运行；取消后界面 SHALL 恢复可输入状态。

#### Scenario: 提交用户消息

- **WHEN** 用户输入内容后按 Enter
- **THEN** 内容作为用户消息提交并开始一次运行

#### Scenario: 运行中取消

- **WHEN** 用户在运行中触发取消
- **THEN** 当前运行停止，界面显示已取消状态并恢复可输入

#### Scenario: 运行状态展示

- **WHEN** 一次运行正在进行或结束
- **THEN** 状态栏相应展示运行中或空闲状态

### Requirement: TODO 面板

界面 SHALL 展示当前 TODO 计划及其状态，并在计划更新时实时刷新；没有计划时 SHALL 显示空状态。

#### Scenario: 计划实时刷新

- **WHEN** TODO 更新事件到达
- **THEN** 面板中的条目与状态同步更新

#### Scenario: 空计划

- **WHEN** 当前没有 TODO
- **THEN** 面板显示空状态，且不挤占对话主区域

### Requirement: 错误呈现

模型、工具或配置错误 SHALL 以可见的错误消息呈现，且界面 SHALL 保持可用、可继续对话。

#### Scenario: 模型调用失败

- **WHEN** 模型调用返回错误
- **THEN** 对话区显示可读的错误说明，输入区恢复可用

#### Scenario: 工具失败

- **WHEN** 工具调用失败
- **THEN** 错误同时出现在工具卡片与对话上下文中
